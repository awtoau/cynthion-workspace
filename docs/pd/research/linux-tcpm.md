## 4. REPLIES / ERROR HANDLING

### 4a. Unsupported message replies
- Ctrl unknown or unsupported: `REJECT` if negotiated_rev < 3.0 else `NOT_SUPP` (tcpm.c:3843-3852 default; also used at 3810-3840 for GET_SOURCE_CAP_EXT, GET_STATUS, FR_SWAP, GET_PPS_STATUS, GET_COUNTRY_CODES, GET_REVISION fallthrough, GET_SINK_CAP_EXT).
- Data unknown: same pattern (tcpm.c:3504-3517 default; Battery_Status and Get_Country_Info at 3503-3507).
- Ext unknown or unchunked: NOT_SUPP (tcpm.c:3862-3864, 3905-3912).
- Chunked ext > 26 bytes: CHUNK_NOT_SUPP, which sends NOT_SUPP after 42 ms (3876-3878, 6291-6296).
- SVDM unsupported / unknown: NAK (2484-2491 default, 2271-2275).
- Unstructured VDM on PD2.0: silently dropped (2563-2566).

### 4b. Unexpected messages (soft reset)
- Unexpected ACCEPT, REJECT, WAIT, NOT_SUPP in READY, outside VDM: soft reset (tcpm.c:3676-3690 `tcpm_pd_handle_state(SRC/SNK_SOFT_RESET_WAIT_SNK_TX / SNK_SOFT_RESET)`). Same for unexpected PS_RDY (3596-3601).
- Unexpected Alert outside READY: soft reset (3496-3499).
- Unexpected EXT Status/PPS_Status: soft reset (3889-3892).
- Partner Source_Capabilities while SRC: REJECT/NOT_SUPP (3388-3397 ~), not soft reset.

### 4c. Wait handling
- Source WAIT when VDM AMS running with explicit contract: REQUEST answered by WAIT (3446-3448).
- DR/PR/VCONN swap answered by WAIT when `send_discover && rev < 3.0` (3778-3779, 3794-3795, 3803-3804). Queued via `tcpm_queue_message` (4059).
- Sink receives WAIT in NEG_CAPS: goes to SNK_READY or SNK_WAIT_CAPABILITIES (3608-3619). No REQUEST retry timer in code. INFERRED: spec expects re-send after tSinkRequest (PD_T_SINK_REQUEST 100 ms, pd.h:662), which is unused in tcpm.c (grep).
- Sink PPS WAIT -> aug_supply_req_status = -EAGAIN (3623-3634 ~).
- DR/PR/VCONN WAIT -> swap_status = -EAGAIN (3641-3656 ~).

### 4e. Transmit path (tcpm.c:1102-1174)
- Waits up to PD_T_TCPC_TX_TIMEOUT 100 ms (tcpm.h:32) for TX completion. Timeout -> -ETIMEDOUT (1132-1137).

### 4g. Collision avoidance (Rp SinkTxNG / SinkTxOk)

- Source: AMS finish sets SINK_TX_OK for PD3.0, SINK_TX_NG for PD2.0 (tcpm.c:1090-1094).
- Source: before first message of AMS, waits PD_T_SINK_TX 16 ms if cc_req == SINK_TX_OK (1720-1730; also VDM INIT at 2803).
- Sink: refuses non-interruptible AMS when `!tcpm_sink_tx_ok` (rp 3.0 not seen) -> -EAGAIN (1737-1742). Macro tcpm.c:767-769.

## 5. FUSB302 SPECIFICS (fusb302.c, fusb302_reg.h)

### 5a. Init
- tcpm_init (fusb302.c:~391-420): sw reset (fusb302.c:336-344), auto-retry N=3 (`FUSB_REG_CONTROL3_N_RETRIES_3 | AUTO_RETRY`, 405, 350-357), interrupt init (364-378: MASK all but VBUSOK; MASKA all masked; MASKB all masked; INT_MASK cleared), power all (`FUSB_REG_POWER_PWR_ALL`).
- Retry bit values: RETRIES_3 = 0x6, RETRIES_2 = 0x4, RETRIES_1 = 0x2, AUTO_RETRY = bit0 (fusb302_reg.h:66-71).

### 5b. TX FIFO token sequence (fusb302.c:964-1011, `fusb302_pd_send_message`)
Written in one I2C block to FIFO reg 0x43 (`FUSB_REG_FIFOS`, fusb302_reg.h:162; written at 1004).
Sequence:
1. SOP: `SYNC1`(0x12) x3, `SYNC2`(0x13) (973-976). Note SYNC3 (0x1B) defined (fusb302_reg.h:168) but not used in this path.
2. `PACKSYM | len` (0x80 | len), len = cnt*4 + 2 (header included) (980-987). Reject if len > 0x1F (977-983, returns -EINVAL). Max 7 data objects.
3. Header (2 bytes LE) (988-990).
4. Payload cnt*4 bytes (991-994).
5. `JAMCRC` (0xFF) (996). Hardware computes CRC.
6. `EOP` (0x14) (998).
7. `TXOFF` (0xFE) (1000).
8. `TXON` (0xA1) (1002).
Token values: fusb302_reg.h:164-175 (TXON A1, SYNC1 12, SYNC2 13, SYNC3 1B, RST1 15, RST2 16, PACKSYM 80, JAMCRC FF, EOP 14, TXOFF FE). RST1 and RST2 are defined but never emitted (INFERRED from the send function only).

### 5c. TX dispatch (fusb302.c:1030-1058)
- TCPC_TX_SOP: sets retry count by rev (1040-1043), then sends message (1044).
- TCPC_TX_HARD_RESET: sets CONTROL3.SEND_HARDRESET (bit 6, fusb302_reg.h:62; fusb302.c:1013-1016).
- Anything else (SOP', SOP'', DEBUG', CABLE_RESET, BIST_MODE_2): "type not supported", -EINVAL (1048-1052). SOP' is not possible on this chip (tcpm.c:2070-2074 requires `cable_comm_capable`; fusb302 does not set it).

### 5d. RX path
- RX is pulled from FIFO in `fusb302_pd_read_message` (fusb302.c:1431-1482): 1 token byte (SOP), 2 header bytes, payload `cnt*4` bytes (limit PD_MAX_PAYLOAD*4 at 1443-1447), 4 CRC bytes read and discarded.
- If `len == 0` and type == GOOD_CRC -> `tcpm_pd_transmit_complete(SUCCESS)` (1477-1478). Else -> `tcpm_pd_receive(...,TCPC_TX_SOP)` (1479-1480).
- Read is triggered by two IRQs: TX_SUCCESS (fusb302.c:~1606-1612) and GCRCSENT (INTERRUPTB, ~1626-1632). So a received message is read after the chip sends its auto-GoodCRC.
- `fusb302_pd_rx_flush` and `fusb302_pd_tx_flush` run on every set_pd_rx change (fusb302.c:792-801, 839-870).

### 5e. Auto GoodCRC and spec revision
- Auto-GCRC bit: SWITCHES1.AUTO_GCRC (bit 2, fusb302_reg.h:26), set/cleared in tcpm_set_pd_rx (fusb302.c:804-810, 839-870).
- TCPM turns PD RX off in HARD_RESET_START (tcpm.c:5831-5840 ~) and on in SNK_WAIT_CAPABILITIES (tcpm.c:5608-5611) and SRC_HARD_RESET_VBUS_ON (tcpm.c:5874-5875 ~).
- Spec revision: the driver never writes a revision field into GoodCRC. The chip sends GoodCRC with its own rev bits. INFERRED: GoodCRC is always 2.0/3.0 as the chip decides, and the 2.0/3.0 choice is only visible through TX retry count (fusb302.c:1040-1043). Header rev for data messages comes from negotiated_rev (tcpm.c:1381-1397, 1420-1428, PD_HEADER_LE calls).

### 5f. IRQ handling (fusb302.c:1502-1636, `fusb302_irq_work`)
| Interrupt | Action | Lines |
|---|---|---|
| VBUS_OK | tcpm_vbus_change | ~1527-1536 |
| TOGDONE | fusb302_handle_togdone (SNK 1189, SRC 1307, dispatch 1393) | ~1538-1545 |
| BC_LVL | delayed work, 30 ms debounce (T_BC_LVL_DEBOUNCE_DELAY_MS, fusb302.c:45) | ~1547-1553 |
| COMP_CHNG | comp -> CC open, tcpm_cc_change | ~1555-1565 |
| COLLISION (INTERRUPT bit 1) | TX_FAILED (tcpm.c:1163) | 1581-1586 |
| RETRYFAIL (INTERRUPTA bit 4) | TX_FAILED | 1588-1591 |
| HARDSENT (A bit 3) | fusb302_pd_reset (PD_RESET bit, fusb302_reg.h:88; fusb302.c:1425-1428), TX_SUCCESS | 1596-1601 |
| TX_SUCCESS (A bit 2) | read FIFO (GoodCRC or message) | ~1604-1610 |
| HARDRESET (A bit 0) | fusb302_pd_reset, then tcpm_pd_hard_reset | ~1613-1620 |
| GCRCSENT (B bit 0) | read FIFO (our received message) | ~1622-1632 |

Not handled: SOFTRESET (A bit 1), SOFTFAIL (A bit 5), OCP_TEMP (A bit 7). Not unmasked in pd_set_interrupts (fusb302.c:813-830) and absent from irq_work. INFERRED: Soft_Reset is handled purely as a PD message by TCPM.

### 5g. Masks set when PD RX enabled (fusb302.c:813-837)
- MASK: COLLISION (fusb302_reg.h:79).
- MASKA: RETRYFAIL, HARDSENT, TX_SUCCESS, HARDRESET (fusb302_reg.h:94-98).
- MASKB: GCRCSENT (fusb302_reg.h:100).

### 5h. Hard reset sequence (fusb302)
- TX: TCPM calls `tcpm_pd_transmit(TCPC_TX_HARD_RESET, NULL)` (tcpm.c:1695, 1748) -> CONTROL3.SEND_HARDRESET (fusb302.c:1013-1016). Completion via HARDSENT IRQ -> PD_RESET bit -> TX_SUCCESS (fusb302.c:1596-1601).
- RX: HARDRESET IRQ -> PD_RESET -> tcpm_pd_hard_reset (fusb302.c:~1613-1620; tcpm.c:6941-6948).
- PD_RESET clears the PD block (INFERRED from name; fusb302_reg.h:88).

### 5i. Toggling and CC
- tcpm_start_toggling (fusb302.c:923-~955): modes OFF, DRP, SNK, SRC (`TOGGLING_MODE_*`, fusb302.c:48-50). Source current from cc_src_current table (`fusb302_set_src_current`).
- Toggling resolved in TOGDONE handler (fusb302.c:1189-1306 SNK, 1307-1392 SRC).
- BC_LVL -> CC status mapping: `fusb302_bc_lvl_to_cc` (fusb302.c:1057-1066 ~).

### 5j. Not implemented by fusb302 (tcpc hooks absent)
`cable_comm_capable`, `attempt_vconn_swap_discovery`, `enable_frs`, `set_bist_data` (grep: absent). Consequences: no SOP', no FRS, no BIST testdata, no vconn-swap-for-discovery (tcpm.c:2070-2115, 2117-2135, 3485-3471 FRS, 6225-6228).

### 5k. Collision IRQ
COLLISION -> TX_FAILED. TCPM caller treats as -EIO (tcpm.c:1163-1165). For SRC_SEND_CAPABILITIES retry at 5290-5292 (`PD_T_SEND_SOURCE_CAP`).

## Notes on scope
- TCPM contains no DisplayPort, Thunderbolt, or other SVID-specific VDO logic. Those VDOs are passed through to altmode drivers (tcpm.c:2620-2626, 2634-2640). typec_dp.h and typec_tbt.h define fields that TCPM does not read.
- Structured VDM Enter/Exit replies from the altmode driver are queued asynchronously (tcpm.c:1821-1852), which may order differently from the NAK built in the same call (tcpm.c:2271-2281, 2508). INFERRED: this path was not fully traced.
- Not read in depth: tcpm_pd_send_request/build_request (4431-4510), tcpm_pd_check_request (4124-4183), pps/avs paths (4184-4650), tcpm_pd_event_handler (6840-6990), tcpm_reset_port (4896-4950), attach/toggle state machine (5150-5530, 6360-6720), tcpci.c, tcpci_*.c, and the rest of fusb302.c (toggling, CC, VBUS).
